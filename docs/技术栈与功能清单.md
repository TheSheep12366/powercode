## 一、技术栈（定稿）

| 层次 | 选型 | 版本 / 说明 |
|---|---|---|
| 运行环境 | **Node.js** | 22 LTS（前后端同语言，实时协作生态最全） |
| 语言 | **TypeScript** | 前后端共享类型定义 |
| 后端框架 | **Express 5** | REST API |
| 应用实时通信 | **Socket.IO 4** | 终端数据流、在线状态、系统通知 |
| 协作引擎 | **Yjs + @hocuspocus/server** | CRDT 算法；Hocuspocus 与主服务共用一个 HTTP 端口，提供文档级鉴权钩子与持久化钩子 |
| 前端框架 | **Vue 3 + Vite + Pinia + Vue Router** | 组合式 API |
| UI 组件库 | **Element Plus** | 表格（搜索/排序/分页）、树、表单开箱即用，天然适配管理面板 |
| 代码编辑器 | **CodeMirror 6 + y-codemirror.next** | Yjs 官方协作绑定，远程光标（带用户名标签）、选区高亮内置 |
| 浏览器终端 | **Xterm.js**（+ fit / web-links 插件） | |
| 终端后端通道 | **ssh2** | 平台后端 SSH 连接本机 sshd，以用户自己的系统账号执行命令 |
| 数据库 | **SQLite**（better-sqlite3，WAL 模式）+ **Drizzle ORM** | 零部署；schema 保持可迁移到 PostgreSQL |
| 密码哈希 | **bcrypt** | cost 12 |
| 会话 | **Cookie Session**（httpOnly + SameSite=Lax），会话存 SQLite 表 | 可随时服务端吊销 |
| 参数校验 | **zod** | 所有 API 入参 |
| 文件监听 | **chokidar** | 检测 SSH/Git 等外部修改 |
| 日志 | **pino** | 结构化 JSON 日志 |
| 反向代理 / TLS | **Nginx + certbot** | WebSocket 升级、强制 HTTPS |
| 进程管理 | **宝塔 Node 项目（底层 PM2 守护）或 systemd** | 有宝塔用宝塔托管（面板可看日志/重启/开机自启）；无宝塔环境走 systemd。安装脚本二选一，我们不直接操作 PM2 |
| 工程结构 | **pnpm workspace（monorepo）** | `apps/server` + `apps/web` + `packages/shared` |

### 选型理由（为什么不用 Java / Go / PHP）

- **Node.js**：实时协作的核心生态（Yjs 官方编辑器绑定、node-pty、Socket.IO、Monaco/CodeMirror）几乎全部长在 JS 生态里；Go/Java 需要自研或找质量参差的 OT/CRDT 移植库，PHP 缺少成熟的 PTY 与实时方案。同语言前后端共享类型（目录树、权限模型、消息协议），开发与联调成本最低。
- **CodeMirror 6 而非 Monaco**：`y-codemirror.next` 是 Yjs **官方**绑定，远程光标（彩色+用户名标签）、选区高亮、断线恢复都是内置能力；Monaco 的协作绑定是社区维护的，且包体大、首屏慢。编辑器层做抽象封装，后期若需要 VS Code 级智能提示可整体切换到 Monaco + y-monaco，成本可控。
- **终端走 SSH 而非 node-pty 直启**：node-pty 以其他用户身份起进程需要 root 或复杂 sudo；改为平台后端用 ssh2 连接**本机 sshd**（密钥登录），命令进程天然属于该系统用户，权限边界由操作系统保证，且天然支持后续 chroot / ForceCommand。与需求文档"后端通过 SSH 协议执行命令"完全一致。
- **SQLite 而非一上来 PostgreSQL**：50 人以内规模 WAL 模式绰绰有余，少维护一个数据库服务；Drizzle ORM 保证日后切 PostgreSQL 只改连接配置。

## 二、系统架构

```
浏览器 (Vue 3 SPA)
 ├─ HTTPS REST ──────► Nginx :443 ──► Express API（登录/用户/目录/权限/文件上传下载）
 ├─ Socket.IO ───────►      │       ──► 终端流(piped ssh2)、在线状态、通知
 └─ Yjs WebSocket ───►      │       ──► @hocuspocus/server（CRDT 同步/文档鉴权/写盘）
                             │
                     Express + Hocuspocus（systemd 服务，运行账户 collab-svc，非 root）
                      ├─► SQLite（用户/权限/会话/审计）
                      ├─► 共享目录（磁盘）◄── chokidar 检测外部修改
                      └─► ssh2 ──► 本机 sshd:22 ──► collab-<name> 系统账号（终端/调试命令）

系统账号管理：collab-svc 通过【最小化 sudo 白名单】执行 useradd/userdel/usermod/chpasswd 等
命令白名单：sshd Match User collab-* + ForceCommand 包装脚本校验 + 自动 attach tmux
```

### 五个关键机制

1. **文档落盘**：Yjs 文档更新经防抖（约 1s）写回磁盘，编辑期间以内存文档为准——保证 SSH 登录的用户和 Git 看到的始终是最新内容。
2. **外部修改检测**：chokidar 监听 mtime + hash；检测到 SSH/Git 等外部改动时重载文档并向所有协作者广播（正在编辑的缓冲区提示合并/覆盖）。
3. **权限全链路生效**：目录权限在四个层面同时校验——文件树列表、REST API、Yjs 协作通道（Hocuspocus `onAuthenticate` 钩子）、终端（操作系统文件权限兜底）。`deny` > `rw` > `ro`。
4. **系统账号同步**：Web 创建用户 → sudo 白名单调用 `useradd` 创建 `collab-<name>` → 平台生成 SSH 密钥对 → 公钥写入该用户 `authorized_keys`，私钥加密存库（供平台代连终端）。
5. **命令白名单（P1）**：sshd 对 `collab-*` 用户配置 `ForceCommand /usr/local/bin/collab-shell`，包装脚本读取平台下发的白名单做校验，并自动 `tmux attach` 实现会话持久化。

## 七、需要你准备的环境

### 硬件 / 系统
- Linux（**Ubuntu 22.04/24.04 或 Debian 12** 均可，当前这台 WSL2 机器可直接开发，生产另备真机）
- 开发机 4C/8G 已满足；生产 50 人建议 4C/8G 起

### 软件清单（需要安装）

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install -y git curl nginx build-essential python3 openssh-server

# Node.js 22 LTS（NodeSource 源）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# pnpm
sudo npm i -g pnpm

# 可选（生产 HTTPS）：certbot
sudo apt install -y certbot python3-certbot-nginx
```

### 依赖说明
| 组件 | 用途 | 备注 |
|---|---|---|
| OpenSSH Server | Web 终端代连的本机 sshd | 需开启公钥认证（默认已开启）；平台依赖它做权限隔离 |
| Nginx | 反代 + TLS + WebSocket 升级 | 若用宝塔，可直接用宝塔的 Nginx 建站反代到 Node 端口 |
| build-essential + python3 | 编译 better-sqlite3 原生模块 | node-gyp 需要 |
| ~~PostgreSQL / Redis / Docker / PM2~~ | **都不需要装** | SQLite 内嵌；v1 单机 systemd；Redis/Docker 是 v2 的事 |

### 宝塔面板部署方式（已确认采用）

- 「网站 → Node项目 → 添加Node项目」选 **默认项目**：底层即 PM2 守护（官方文档确认），自动重启、开机自启、面板看日志。
- 项目目录填仓库根目录 `/www/wwwroot/powercode`，启动脚本读取根 package.json 的 `start`（即 `node apps/server/dist/index.js`），Node 版本选 22.23.2，项目端口 3000。
- **不勾选面板的"安装依赖"**：monorepo 使用 pnpm workspace，面板的 npm install 在 workspace 下会出错；依赖安装与构建由部署脚本在 SSH 下执行（`pnpm install && pnpm build`）。
- 运行用户：优先选 `collab-svc`（部署脚本先创建该用户）；若面板的用户下拉不支持自建用户，则放弃宝塔管进程改走 systemd，宝塔仅保留建站/反代/SSL。
- 反向代理：宝塔 Node 项目自动生成外网映射，需确认配置含 WebSocket 升级头（`Upgrade` / `Connection`），缺失时由部署脚本补齐——终端和 Yjs 协作都依赖 WebSocket。
